画面 3 · 档案同步控制台 + 手动关联（自动建联之外的兼容层）

路径契约只能解决规范文档的自动归因。现实里三类情况必须手工接手：① 存量旧目录只有 requirement_key 没有 multica_issue_id；② 文档写在业务仓、路径不遵守契约；③ 一份文档该归哪个需求有争议。所以同步必须可配（模式 / 范围 / 冲突策略）、可诊断（分级日志 + 降级原因），关联必须可改（待绑定队列给候选 + 编辑器可覆盖契约）。覆盖不靠静默写 DB：默认写回 frontmatter 并 git commit，保证本地 IDE 与 multica 看到同一份事实；仅当用户显式选「仅改 DB 指针」时才记 source='manual' + override_reason，且下一次 sync 不会被路径契约冲掉。
