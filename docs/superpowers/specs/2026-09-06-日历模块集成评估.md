# 日历模块集成审计（对照提升设计 + 原型 7 画面）

- 日期：2026-09-06（代码实证）
- 对照：
  - `2026-09-06-calendar-module-elevation-design.md`（IA 契约，高于原型 f1）

- 结论：**提升设计的入口骨架已落地；原型七个画面没有按能力完整集成。** 日历是「找得到、点得开、四阶段能挂上」的组装，不是原型级确认工作台。

## 0. 总判断

| 层 | 完成度 | 说明 |
|---|---|---|
| 提升设计 · 路由 / 侧栏 / 去 Issues 日历 tab | ~90% | web 齐；**desktop 未注册 `/calendar` 路由** |

| 原型 f3 创建 | ~85% | 创建弹窗字段已齐，日历页复用 |
| 原型 f4–f7 四阶段 | ~55–80% | 抽屉复用 FlowSection，面板深度仍是「能走通」不是「按标注做满」 |

## 3. 集成裂缝（按用户能感知的顺序）

1. **桌面端日历是断的** — 侧栏有入口，`routes.tsx` 无路由。
2. **日历不是全量需求** — 每状态类目只取首页 50 条。
3. **工具栏比提升设计少三件** — PM、拆解状态、待确认 chip；代码自称二期，设计未授权降级。
4. **抽屉关了色块不刷新** — 确认/触发后列表缓存不失效。
5. **抽屉头 / 需求列表卡薄于设计** — 无班底头像；列表无阶段进度。
6. **f5/f4/f6/f7 仍是「能走通的面板」** — 与提升前详情页同一套，不是按原型标注做满。
