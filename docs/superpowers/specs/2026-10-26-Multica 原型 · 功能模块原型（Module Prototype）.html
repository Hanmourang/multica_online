画面 2 · 现状的六条硬伤与优化取向

逐条从代码取证，每条都给「改在哪一层」，避免把问题落到样式上。核心判断：原型能力已经很强，缺的不是渲染，而是「模块作为第一主体的归属与对账」。

差距分析GAP → 取向
1原型没有「模块权威指针」
project_module 只有 7 列，没有 canonical 版本；issue_prototype_version.status 的 confirmed 是需求级语义。同一模块挂 5 个需求时，谁是「这个页面现在的样子」没有答案。
加 canonical_prototype_version + 「提升为权威」动作；模块头常显「权威 vN」。
2没有规格 ↔ 原型对账
现有 diffFeaturePoints 比的是两个 HTML 版本；marks 只标当前版本内每个 fp 的符合度。缺「模块功能点全集」这一列，空位不可见。
新增「结构对账」视图：行＝规格 FP，列＝规格 / 权威原型 / 候选原型，产出覆盖率。
3无需求即无原型
reqs.length === 0 → 空态「该模块还没有 HTML 原型版本」；关联原型按钮也依赖 reqs。模块无法自助长出一版原型。
空态给两条出路：从会话生成 / 从权威模块复制骨架；原型允许先挂模块再补需求。
4写回只到评论
WriteSummaryButton 把变更摘要 createComment 到需求；结构变更无法写回模块规格，需求评论成为唯一沉淀。
写回目标升级为「模块规格 + 权威指针」；评论降级为旁路通知。
5不能从模块发起会话
setPageContext({surface:"prototype"}) 只把上下文塞进聊天，聊天产物回不到模块版本序列，模块侧看不到「待发布」。
模块侧增加「待发布变更」队列，会话产出先进队列、再一次性发布。
6版本选择器不可扫读
两个下拉（当前 / 对比）+ pickPrototypePair 自动配对；版本超过 4 个后无法一眼看出「哪版是谁产出的、为什么被替换」。
左侧改成纵向版本时间线：来源、产出者、功能点数、对齐率、替换原因。

画面 3 · 优化后：模块详情「原型图」子页（主画面，可交互）

三处结构性改动：① 详情区补模块头，把「模块名 · 权威原型 v2 · 规格 v3 · 覆盖率 80%」一次说清；② 左侧「版本下拉」改为纵向版本时间线，用来源 / 功能点数 / 对齐率 / 替换原因替代两个下拉；③ 右侧检视器升级为结构对账——行是模块功能点全集，列是「规格 / 权威原型」的覆盖态，空位与残留一眼可见。点版本行、点功能点、点「提升为权威」都可试。

画面 4 · 结构对账矩阵：以「模块规格」为行，以「原型版本」为列

这是本次最重要的新视图。As-Is 的对比永远发生在两个 HTML 版本之间，所以只能回答「改了什么」；矩阵回答的是「模块承诺的功能点，现在兑现了几个」。四种覆盖态互斥可计数，覆盖率 = 已覆盖 ÷ 规格功能点，直接成为模块头的那个环。点「登记为规格功能点」可试。

画面 7 · 状态机与数据契约

把上面的交互压成可实现的字段与状态。原则：不新增原型存储——原型仍然落在 issue_prototype_version 与磁盘 HTML 上，只给 project_module 补三列、给版本补一个可空的 module_id，其余是投影。

project_module.canonical_prototype_versionint null新增模块当前权威原型版本号。NULL ＝ 尚无权威原型（空态如实显示，不自造默认值）。只能指向该模块下 status='confirmed' 的版本。

issue_prototype_version.module_iduuid null新增让原型可以只挂模块、不挂需求。有了它，「无需求即无原型」才被真正解开；一版原型最多属于一个模块。
issue_prototype_version.statustext沿用语义收紧为 draft → pending → confirmed → superseded；superseded 只由「设为权威」触发，不再由任意更新触发。

画面 8 · 交互、空态与边界

这几条决定上线后会不会被骂：空态必须有出路、失败必须能回滚、权限必须能收窄。

交互规格EDGE CASES
场景行为
模块无任何原型不再只显示「该模块还没有 HTML 原型版本」。改为两条出路：①从对话生成（起会话，挂 module + 空原型）；②从模板起骨架（复制同类模块的 data-fp 骨架）。两者都产出 draft，需发布才成权威。
模块有原型但无规格对账矩阵整列显示「规格未建立」，顶部提示「先用当前权威原型生成 v1 规格」；一键从 data-fp 反向生成 spec（生成后 spec_version=1）。
原型未标注 data-fp沿用现有兜底：按标题 / 导航抽模块，并在矩阵里给行加 推断 标记，覆盖率不计入分子（避免虚高）——这比现在「静默推断」更诚实。
发布时版本被抢占expected_version 不匹配 → 整笔回滚 + 提示「模块规格已被他人推进到 v5，请重新对账」。绝不部分提交。
废弃影响已验收功能点二次确认弹窗列出受影响的需求 / 验收项，默认不勾选「同时作废验收」；作废需另一条独立动作，留审计记录。
权限查看原型与对账：项目成员；登记功能点 / 设权威 / 发布：项目 owner 或 module:write。Agent 只有 module:propose，无 module:publish。
flag 关闭原型子页完全回落到现状实现；已写入的 canonical_prototype_version 只读保留，不参与渲染，重新打开后无需回填。
性能矩阵走 module_prototype_link 单次查询（目标 P95 < 120ms / 500 功能点）；HTML 预览仍按现有 useArchivePreviewSource 懒加载，切版本不预取其余版本正文。
