| 层 | 谁消费 | 枚举 | 能否出现在路径里 |
|---|---|---|---|
| **货架（shelf）** | CONTRACT §1、C2 四张卡、`archive sync`、巡检 | `research` · `product-design` · `architecture` · `retrospective` | **必须**。`projects/<key>/overview/<shelf>/` |

| 分类法 | 落入货架 | 理由 |
|---|---|---|
| `research` · `diagnosis` · `selection` | `research` | 调研 / 根因 / 选型都是立项与问题分析 |

| `retrospective` · `report` · `summary` | `retrospective` | 复盘、汇报、一页纸都是事后资产 |

需求级类型（`requirement` / `prototype` / `plan` / `decomposition` / `design` / `test-plan` / `deliverables` / `run` / `acceptance` / S4 `report`）**不进 overview**。无 `REQ-KEY` 时进 `_shared/inbox/`，禁止猜一个需求目录。

## 4. 目录骨架（机器可解析，沿用 09-07）

```
projects_mgmt/
├── CONTRACT.md
├── projects/<project_key>/
│   ├── PROJECT.md
│   ├── overview/{research|product-design|architecture|retrospective}/
│   ├── requirements/<REQ-YYYYMMDD-NN>/{requirement.md,s1..s4}
│   ├── filing/{software-copyright|patent}/
│   └── change_logs/daily_logs/          # 可选镜像
├── _shared/{sop,templates,tools,research,design-system,inbox,reports}/
├── _attic/                              # 本地留存，不索引
└── docs/                                # 仓级，非项目档案
```

历史顶层（`0.*` / `1.requirements` / `2.spec_infos` / `3.phone_agent` / `4.技术方案`）在迁完前是**待处理区**，不是合法货架。sync 不得把它们假装已归档。

硬规则补强：

1. 目录片段英文 kebab-case；文件名可中文，禁止空格与 `\/:*?"<>|`。
2. 附件跟文档走同级 `assets/`；构建产物与 `node_modules` **不是**附件。
3. `page-navigator` 这类带依赖的工程副本：最多迁 1 份 README / 架构说明到 `overview/architecture/`，整树不进 `projects/<key>/assets/`。
4. 改灵敏度只改 `projects.yaml`（`scoring` / `legacy_prefixes` / `skip_*` / `shelf_fold`），不改引擎代码。
5. `apply` 默认 dry-run；不覆盖、不删除；冲突转 review。

## 5. 识别：六源级联（已实现，本方案冻结语义）

| 源 | 信号 | 典型动作 |
|---|---|---|
| L1 路径契约 | 已在 `projects/<key>/…` 且合规 | `in-place` |
| L2 frontmatter | `project_key` / `doc_type` / `multica_issue_id` | 显式优先 |
| L3 启发式 | `legacy_prefixes` · `shared_prefixes` · 文件名矩阵 · 目录指纹 · 别名 | 存量主通道 |
| L4 内容嗅探 | `repo_roots` + keywords | 无前缀的散落文档 |
| L5 LLM | 本工具不内置调用，只标 `suggested_source=L5` | 低置信建议 |
| L6 人工 | 全程未识别 | `_shared/inbox/` |

置信度（注册表 `scoring`，改表不改代码）：

| 档 | 条件 | 动作 |
|---|---|---|
| high ≥85 且领先次名 ≥15% | 可自动归位 | `move` |
| med ≥60 | 必须人工确认 | `review` |
| low | 不硬猜 | `inbox` |

`legacy_prefix` 命中视为决定性 high，但 **skip / attic 优先于 legacy**，避免「前缀对了、对象是 dist」仍被搬走。

## 7. 分波迁移（唯一允许的存量整理节奏）

禁止对 1951 条 `apply --apply` 一次跑完。波次写在注册表 `migration_waves`，CLI `--wave A`。

| 波 | 范围 | 预估可迁 | 完成定义 |
|---|---|---|---|
| **A** | `0.产品设计/` · `0.调研/` · `1.requirements/` | <40 | 小树进 `projects/multica|dsh_desktop|projects_mgmt` 或 `_shared`；`README.md` 进 inbox |
| **B** | `2.spec_infos/` | ~400 | eleme-agent / ontology / knowengine / dsh / multica 进各自 `overview/architecture/` |
| **C** | `3.phone_agent/` 且排除 `page-navigator/` | ~400 | accio / AI阅读文档与 stitch 原型进货架；产品风格进 `_shared` |
| **D** | `page-navigator` 仅根 `README.md` / `index.html` | 2 | 说明文档进 `projects/ai_reading/overview/architecture/`；其余 skip |
| **E** | `_shared/inbox/` + frontmatter 补 `multica_issue_id` | 待绑定队列 | 画面 3 消化；禁止改目录名为 `SIRI-29` |
| **F** | `multica archive sync --project <key>` | 指针 | C2 能看见已迁文件；Web 不得报「同步完成 0/0/0」 |

每波纪律：

1. `recognition` + `plan --wave X --out _shared/archive/reports/YYYYMMDD-归类-waveX.md`
2. 人读 high 清单（抽查目标货架是否落在 4 类之内）
3. `apply --wave X --tier high` dry-run → 确认后 `--apply`
4. `doc_inspector.py scan`：本波新增路径无「overview 类目非法」
5. 该项目 `archive sync`
6. 下一波

`apply` 只迁 `move`；`review` 必须人工改注册表或 frontmatter 后再跑。默认不提交 git commit（用户明确要求再提交）。

CONTRACT §5 仍是一次性映射说明书；**执行引擎改为分类器 + 波次**，`migrate-archive-structure.sh` 降为对照表，不再整树搬 `page-navigator`。
