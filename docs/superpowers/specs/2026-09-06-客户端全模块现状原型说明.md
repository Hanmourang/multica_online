## 1. 为什么先画现状

日历 / 档案 / 交付物已经有目标态深稿，但改进时如果只看深稿，容易把「还没做的目标」和「用户此刻看到的壳」混在一起。本原型把侧栏 13 个入口 + 详情/弹窗一次摊开，作为改进的对照底板。

## 4. 现状里已经对齐的关键事实

- 日历是工作区一级入口；Issues / 我的任务 **没有** Calendar tab。
- 项目详情 6 TAB：任务概览 / 档案 / 产品功能 / 数据模型 / 申报就绪度 / 需求详情。
- 日历工具栏已有：全部项目 / 全部 PM / 全部状态 / 待确认 N / 新建需求。
- 需求抽屉复用 `RequirementFlowSection`，头上有编号、10 态徽标、班底头像、时间窗。
- 四阶段条只出现在顶层且带日历字段的需求上。
- 统计在侧栏叫「统计」，路由是 `/usage`。
- 设置分「我的账号」+「工作区」；桌面端额外 Daemon / Updates。
