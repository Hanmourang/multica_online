## 1. 一句话

Multica **不读盘、不另建分类法**。识别与落盘在本机按 `_shared` 做完；产品只存指针、做检索、关门、从模板快建。PRD / MRD / 路线图是**别名**，折进已有四货架或 REQ 阶段文档，不增加 C2 第五张卡。

## 3. 四件事怎么接到产品上

### 3.1 识别

流水线只允许这一条：

```
磁盘文件
  → _shared 分类器（L1–L4，skip/attic/inbox，12 类折 4 货架）
  → 合法路径 projects/<key>/… 或 change_logs/<key>/…
  → CLI parseArchiveRelPath（与 CONTRACT 同表）
  → 全量清单 sync
  → project_artifact 指针
  → C2 / 检索
```

职责切分：

- **本机（唯一认文件的地方）**：归类、搬家、frontmatter、`doc_class`（prd/mrd 等别名）。
- **CLI**：只扫契约路径；把 `doc_type`（货架/阶段）和 frontmatter 的 `multica_issue_id` / `doc_class` 带进清单。
- **Server**：校验清单字段、差量写指针、记 `sync_diagnostics`。禁止在服务端再发明一套关键词分类。

产品画面：

- 画面 2：Desktop「同步档案」必须提交 CLI 同一份清单（禁止 0/0/0 假成功）。
- 画面 3：inbox + 缺 `multica_issue_id` 的 REQ 文档 = 待绑定。候选仍是标题相似 + 时间窗。
- 画面 4：直接渲染 `doc_classifier.py recognition --format json`（覆盖率、命中源、失败归因），不要平行做一套 LLM 归类 UI。

存量仍按 09-13 分波 A–D `git mv` 后再 sync。未迁的历史目录 **识别得出、入库不得装已经归档**。

### 3.2 检索

索引对象是指针行，不是再扫盘。

| 检索面 | 数据 | 用法 |
|---|---|---|
| 结构筛 | `scope` · `stage` · `doc_type`（货架/阶段）· `issue_id` | 已有 List API |
| 别名筛 | `doc_class`（prd / mrd / brd / roadmap，来自 frontmatter） | **补**清单字段 + query |
| 文本 | `title` / `rel_path` / 文件名 / `doc_class` | List `?q=` 服务端 ILIKE |
| 缺件 | `stage_gate_rule` blocking − 已入库 | 「仅看缺件」只数门，不数任意文件 |
| 未绑定 | `requirement_key` 有、`issue_id` 空 | 画面 3 队列，不算 C2 红框 |

C2 类型筛增加「规划」虚拟组 = `doc_class ∈ {prd,mrd,brd}` 或路径在 `overview/research|product-design`。底层 `doc_type` 仍是四货架。

### 3.3 快速构建项目档案映射

「映射」= 三件事一次对齐：磁盘目录、`projects.yaml`、Multica `archive_resource_id`。

新项目最短路径：

1. **注册**：`projects.yaml` 加 `key` / `name` / `aliases` / `repo_roots`。
2. **脚手架**（本机，建议 CLI `multica archive init --project <key>`）：
   - `projects/<key>/PROJECT.md`（`multica_project_id`）
   - `overview/{research,product-design,architecture,retrospective}/`
   - 从 `_shared/format/templates/` 落 **architecture**（blocking）+ 可选 MRD / 项目级 PRD
   - 空 `requirements/`、`filing/`
3. **绑根**：Desktop「绑定档案目录」指向该 `projects/<key>`，回写 `archive_resource_id` 到 yaml 与 DB。
4. **真 sync**：`multica archive sync --project <key>`。
5. **第一条需求**：日历/侧栏创建 issue → 分配 `REQ-YYYYMMDD-NN` → 写 `requirement.md`（已填 `multica_issue_id`）→ 四个空阶段目录。

已有存量项目：不 init，走分类器 wave + 绑根 + sync。禁止为了对上 `SIRI-29` 改目录名。

脚手架禁止生成：`overview/diagnosis/`、整树 `assets/page-navigator`、业务仓根下一份平行「档案」。

### 3.4 PRD / MRD / 规划文档

人说的「PRD、MRD」不是新货架。映射权威见 `format/规划文档映射.md`。摘要：

| 人口语 | 落点 | `doc_type` | `doc_class` | 进哪张卡 / 哪列 |
|---|---|---|---|---|
| MRD / BRD / 立项调研 | `overview/research/` | `research` | `mrd` / `brd` | C2 调研卡 |
| 项目级 PRD | `overview/product-design/` | `product-design` | `prd` | C2 产品设计卡 |
| 需求级 PRD（对一条 issue） | `requirements/<REQ>/requirement.md` | `requirement` | `prd` | 矩阵行，不是上半区卡 |
| 季度/路线图 / 会话计划 | `change_logs/<key>/plans/` | `work-plan` | `roadmap` | 检索得到，**不关 S2 门** |
| 已确认拆解计划 | `s2-plan/plan.md` | `plan` | — | S2 列 |

产品「从模板创建」下拉应同时显示人口语（PRD/MRD）和货架名；写入时用上表。`archive-templates.ts` 必须与 `_shared/format/templates/` **同源**（生成或复制，禁止再手写一套章节）。

## 5. 人怎么用（空态必须诚实）

1. **新项目**：init → 绑根 → 选「MRD / 项目 PRD」从模板建 → sync → 再开需求。
2. **已有盘、档案空**：先 wave 迁到 `projects/<key>/`，再 sync；不要在矩阵里手搓假 chip。
3. **写 PRD**：问清是项目级还是需求级；需求级只改 `requirement.md`，不要在 overview 再留一份互相漂移的正本（overview 可放「总 PRD」，REQ 放切片）。
4. **检索**：先筛货架或「规划」组，再搜标题；对不上需求进待绑定。

空态：

- 未绑根 → 「先绑定 `projects_mgmt/projects/<key>`」
- 已绑未 sync → 「本机 `multica archive sync --project <key>`」
- 已 sync 未绑定需求 → 「N 份在待绑定」
- 门未闭 → 「S2 缺 plan / decomposition」这类具体缺件
