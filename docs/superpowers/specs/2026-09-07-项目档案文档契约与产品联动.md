## 1. 问题：档案「看不见」文件和交付物

当前项目档案 Tab 经常是空矩阵 / 缺件红框，不是巡检规则写错这么简单，而是**四条写入通道只有人工补档在 Web 侧半通**：

| 通道 | `source` | 产品职责 | 现状 |
|---|---|---|---|
| 目录同步 | `sync` | CLI 扫 `projects_mgmt`，按契约入库 | Web「同步档案」提交空清单 → 服务端 no-op；真实 sync 必须跑 `multica archive sync` |
| 流水线投影 | `server` | 原型版本、拆解 plan、验收报告从 issue 表单向投影 | 未作为档案行自动补齐；工作台有产物、矩阵没有 chip |
| 任务归档 | `agent` | 子任务完成后把交付物写入约定目录并登记 | 任务详情交付墙有路径，多数未 `POST .../archive` |
| 人工关联 | `manual` | 待绑定、改判、从模板补齐 | 控制台 UI 在，但没有待绑定队列数据（sync 没跑过） |

叠加三个事实缺口：

1. **`projects/<key>/` 尚未成为事实目录**。存量仍在 `0.调研/`、`1.requirements/` 等历史路径，契约解析器一律判 orphan，sync 拒收入库。
2. **需求键对不上**。档案目录用 `REQ-YYYYMMDD-NN`，日历 / 工作台用 `SIRI-29` / `issue.id`。没有 `multica_issue_id` 的文档进待绑定，矩阵行对不上需求。
3. **阶段门与 SOP 清单曾不一致**。`stage_gate_rule`（migration 460）把 design / test-plan 放在 S3；旧 SOP 把它们放在 S2。矩阵缺件与巡检缺件互相打架。

**产品原则（沿用画面 1 三条不变量）**：Git 是文档实体唯一事实源；DB 只存指针；`issue_prototype_version` 是原型权威（artifact 只投影）；server 永不读文件系统。

## 2. 一张表：项目要哪些文档

权威优先级：`stage_gate_rule`（运行时门）= 本表 **blocking** 列；`checklist.yaml` 必须与之同构；路径以 `CONTRACT.md` 为准。

### 2.1 项目级（`scope=project`，无 stage）

| 文档 | `doc_type` | 目录 | 格式 | 必备 | 谁写 | 交互 |
|---|---|---|---|---|---|---|
| 项目登记 | `project` | `projects/<key>/PROJECT.md` | md + frontmatter `multica_project_id` | 推荐 | 创建项目时从模板生成 | C2 上半区标题卡；缺则无法自动绑定 archive 目录 |
| 立项调研 | `research` | `overview/research/` | md | 推荐 | 人 / 调研 agent | 双击预览；搜索标题 |
| 产品设计 | `product-design` | `overview/product-design/` | md / 图（`assets/`） | 推荐 | 人 / 产品 agent | 同上 |
| 架构总纲 | `architecture` | `overview/architecture/` | md | **blocking** | 人 / 架构 agent | 任务启动必读（SOP 04）；缺则档案徽标红 |
| 项目复盘 | `retrospective` | `overview/retrospective/` | md | 推荐；项目 `completed` 后升 blocking | 人 | C2 复盘卡；完成后缺件红框 |
| 软著材料 | `filing-software-copyright` | `filing/software-copyright/` | md / pdf 索引 | 推荐（申报轨道升 must） | 人 + 导出预检 | C10 就绪度 |
| 专利材料 | `filing-patent` | `filing/patent/` | md | 推荐 | 人 | C10 |
| 变更日志 | `change-log` | 工作区 `change_logs/<key>/daily_logs/` | md（`YYYYMMDD-` 前缀） | 推荐（检索用，不关门） | 人 / agent（任务完成后按 SOP 05） | C2 类型筛 `change-log`；搜索文件名 |
| 工作计划 | `work-plan` | `change_logs/qoder-plans/` | md | 推荐（检索用，不关门） | IDE / agent 计划镜像 | 与 S2 `plan` 分列，禁止混用 |

### 2.2 需求级（`scope=requirement`，行 = 一个 issue）

需求根目录另有一份 **需求单**（不算 stage，但是 agent 进度事实源）：

| 文档 | `doc_type` | 目录 | 格式 | 必备 | 谁写 | 交互 |
|---|---|---|---|---|---|---|
| 需求单 | `requirement` | `requirements/<REQ-KEY>/requirement.md` | md；frontmatter `status` / `updated_at` / `multica_issue_id` | **blocking**（巡检） | 创建需求时自动落盘 | C5 / C6 跳转；进度查询第一事实源 |

四阶段文档（列 = C2 矩阵）：

| 阶段 | 文档 | `doc_type` | 目录 | 格式 | 门 | 写入通道 | 产品交互 |
|---|---|---|---|---|---|---|---|
| S1 原型 | 可视化原型 | `prototype` | `s1-prototype/` 或业务仓 `docs/prototypes/` | `*-v<N>.html` | blocking（可被项目覆盖：未启用原型师则跳过） | `server` ← `issue_prototype_version`；也可 `sync` | B4·S1 确认门；C2 chip 标「投影」；✗ 未处理禁止确认 |
| S1 | 批注快照 | `prototype-marks` | 同目录或投影行 | json / 内嵌 marks | 推荐 | `server` | 点 chip 打开预览 + 批注侧栏 |
| S2 拆解 | 执行计划 | `plan` | `s2-plan/plan.md` | md | **blocking** | `agent`（PM 出草稿）/ `manual` | B4·S2 左栏；确认拆解前必齐 |
| S2 | 拆解明细 | `decomposition` | `s2-plan/decomposition.md` | md + 功能点表 | **blocking** | `agent`；确认后落 `issue.feature_points` | B4·S2 右表明细；确认 → 生子任务 |
| S3 执行 | 实现方案 | `design` | `s3-execution/design.md` | md | **blocking** | `agent` / `manual` | 编码前可读；C2 S3 chip |
| S3 | 测试方案 | `test-plan` | `s3-execution/test-plan.md` | md | **blocking** | `agent` / `manual` | 研发 / 测试共用 |
| S3 | 交付清单 | `deliverables` | `s3-execution/deliverables.md` + 代码文件 | md + 源码路径 | 非 blocking | `agent` 归档 | C9 墙；任务完成自动建议归档 |
| S3 | 执行记录 | `run` | `s3-execution/runs/run-NN.md` | md | 推荐 | `agent` | A3 执行日志深链 |
| S4 验收 | 验收标准 | `acceptance` | `s4-acceptance/acceptance.md`；业务仓 `acceptance/` 为代码断言 | md + spec | **blocking** | `manual` / `agent`；代码走 `sync` | B4·S4 依据段；C8 回炉 |
| S4 | 验收报告 | `report` | `s4-acceptance/report-r<N>.md` | md | **blocking** | `agent`（测试） | 轮次 = `version`；不通过 → 回炉子任务 |

`REQ-KEY` 格式仍是 `REQ-YYYYMMDD-NN`。**对外展示**用 issue 标识（`SIRI-29`）；绑定靠 `frontmatter.multica_issue_id`，不是靠把目录改成 identifier。

## 3. 存放与格式（机器可解析）

```
projects/<project_key>/
├── PROJECT.md
├── overview/{research|product-design|architecture|retrospective}/
├── requirements/<REQ-YYYYMMDD-NN>/
│   ├── requirement.md
│   ├── s1-prototype/          # html · -v<N>
│   ├── s2-plan/               # plan.md · decomposition.md
│   ├── s3-execution/          # design.md · test-plan.md · deliverables.md · runs/
│   └── s4-acceptance/         # acceptance.md · report-r<N>.md
├── filing/{software-copyright|patent}/
└── change_logs/daily_logs/    # 可选镜像；权威在工作区 change_logs/<key>/
```

工作区并列：`change_logs/<project_key>/daily_logs/`（`change-log`）、`change_logs/qoder-plans/`（`work-plan`）。跳过备份树。

硬规则：

- 目录片段英文 kebab-case；文件名允许中文，禁用空格与 `\/:*?"<>|`。
- 版本后置：`*-v<N>` / `report-r<N>.md`；缺省 v1。
- 附件进同级 `assets/`，不进索引。
- frontmatter 显式 `doc_type` + 需求内必填 `multica_issue_id`；与路径冲突时按项目 `conflict_policy`（默认路径优先）。
- 业务仓里的原型 / 验收代码**不是第二事实源**：要么 sync 进档案指针，要么由 server 投影；禁止只活在聊天附件里。

## 4. 产品能力：从「能列出」到「能认全、能关门、能流转」

对齐 C2 + 画面 1/2/3 + C9，能力拆成五层。未打勾的是本期要把产品说清楚、实现上补齐的。

### 4.1 识别与入库（画面 1–2）

| 能力 | 行为 | 完成定义 |
|---|---|---|
| 档案根绑定 | 每个 project 有 `archive_resource_id` → `projects_mgmt/projects/<key>` | 未绑定：C2 空态引导「绑定档案目录」而不是假同步成功 |
| `multica archive sync` | 扫描 → 契约解析 → blob 差量 → 全量清单 diff | 工具栏「同步档案」在 Desktop / CLI 提交真实清单；Web 只做「校验链路」，文案不得说「同步完成 0/0/0」 |
| 分类诊断 | 命中 / frontmatter 补绑 / 无法归类 / 契约拒绝 | 画面 3 流水线五段 + `sync_diagnostics` |
| 存量回填 | 历史路径按 CONTRACT §5 `git mv` 后再 sync | 未迁移文件不得假装已归档 |

### 4.2 关联（画面 3）

| 能力 | 行为 |
|---|---|
| 待绑定队列 | `requirement_key` 有、`issue_id` 空；候选 = 标题相似 + 时间窗 + 标识后缀 |
| 一键绑定 | 写回 frontmatter + git commit（默认）；或 `source=manual` + `override_reason`（仅改指针） |
| 新建并绑定 | 置信度 < 60% 时建议「新建需求」而不是硬猜 |
| 批量绑定 | conf ≥ 85% 可一批提交 |

### 4.3 主视图（C2）

| 能力 | 行为 |
|---|---|
| 上半区项目四卡 | research / product-design / architecture / retrospective；缺件红框 +「从模板创建」 |
| 下半区矩阵 | 行 = 已绑定需求；列 = S1–S4；格内 chip 带来源徽标（投影 / agent / sync / 人工） |
| 仅看缺件 | 按 `stage_gate_rule` blocking 项，不是按「格子里有没有任意文件」 |
| 预览 | 双击 chip → 快照渲染 + 元数据 + 跳 C6 / B4 对应阶段 |
| 档案设置 | 路径规则只读说明 + 项目级覆盖阶段门（关原型师 → S1 门失效） |

徽标「缺 N」= blocking 门未闭合数 + 项目级 architecture 缺失，**不含**未绑定 orphan。

### 4.4 自动化写回（与流水线咬合）

| 流水线事件 | 自动档案动作 |
|---|---|
| 创建需求（日历 / 侧栏「需求」） | 生成 `REQ-KEY` 目录 + `requirement.md`（写入 `multica_issue_id`）；可选登记 `PROJECT.md` |
| S1 原型构建 / 确认 | 投影 `prototype` + `prototype-marks`（`source=server`）；确认后 S1 门闭合 |
| S2 确认拆解 | 落 `plan.md` / `decomposition.md`；`feature_points` 与文档表格同源 |
| 子任务 `task_completed` | 交付墙「归档到档案」默认路径 `s3-execution/`；确认后 `source=agent` + `task_id` |
| S4 测试出报告 | 写 `report-r<N>.md`；不通过自动开回炉子任务，不改已归档 report 版本（只加 r+1） |
| 需求 `accepted` | S4 门必须闭合；触发 C10 就绪度重算 |

### 4.5 交付物双面（C9 ≠ C2）

- **C9 交付物**：看「这次任务交出了什么」（代码、附件、评论声明），实时、偏 run。
- **C2 档案**：看「项目长期资产架上有没有」（契约路径 + 阶段门）。
- 同一文件可以同时出现：C9 是事件，C2 是归档后的指针。未归档的交付物**不算**阶段门齐备。

## 5. 交互形式（人怎么用）

1. **项目经理**：C2 看缺件 → 点需求行进 C6 / B4 → 在阶段面板确认，而不是在矩阵里改文档。
2. **执行人 / agent**：按 SOP 04 三级加载；写文档用模板；提交后由通道自动或「归档」进架。
3. **档案管理员**：画面 3 消化待绑定与无法归类；冲突默认写回 Git。
4. **申报**：C10 只吃已入库 artifact，不扫聊天记录。

空态文案必须诚实：

- 未绑档案根 → 「先绑定 `projects_mgmt/projects/<key>`」
- 已绑但从未 sync → 「在本机运行 `multica archive sync --project <key>`，或用 Desktop 同步」
- 已 sync 但需求未绑定 → 「N 份文档在待绑定」
- 已绑定但门未闭 → 「S2 缺 plan / decomposition」这类具体缺件

## 6. 落地顺序（只补齐识别，不新造机制）

1. **契约对齐**（本文 + SOP 07 + `checklist.yaml` + `ARCHIVE_CHECKLIST` + `stage_gate_rule` 同构）——本期文档。
2. **绑定档案根 + Desktop/CLI 真同步**：Web 不再假装 sync。
3. **server 投影**：原型版本、拆解确认、验收报告写入 `project_artifact`。
4. **完成即归档**：任务交付墙默认路径 + 一键确认。
5. **存量 `git mv`**：CONTRACT §5 迁入 `projects/<key>/` 后再全量 sync。
6. **待绑定队列**真正吃 sync 诊断，而不是空列表。

不在本期发明：新的需求表、第二套状态机、Web 读本地磁盘、假数据填矩阵。
