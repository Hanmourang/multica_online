画面 2 · 版本异动：一行一个功能点，一列一个版本，右侧直接回答「哪个需求动了哪些功能点」

这张矩阵替代了原来的「变更概览」+「并排对比 + HTML 行 diff」三套割裂视图：行 = 功能点全集（含已移除与草案），列 = 版本，单元格只允许五种态（新增 / 变更 / 未变 / 移除 / 未包含），下方再把每个需求声明的功能点与实测改动并排放——越权就是「实际 − 声明」这张差集，不再靠人眼对 HTML。

画面 3 · 功能点详情：一个功能点必须能说清「是什么、怎么交互、怎样算达成、落在哪段代码」

这是「模块对象 + 模块策略」被合并后的落点。左栏是产品语义（区域 / 元素锚点 / 功能说明 / 交互详情 / 验收目标），右栏是工程与过程证据（实现映射、版本轨迹、关联需求任务、越权记录）。图谱对象与策略键只作为实现映射的证据出现，用户不再需要在两个 TAB 之间自己对号。

① 功能说明 产品语义

在申报单行内提供撤回入口。v2 撤回即时生效并写审计；v3 起撤回进入审批流（提交 → 待审批 → 已撤回/已驳回），撤回原因必填且不可少于 10 字。

区域行操作 · 列表区第 4 列
元素锚点button.row-revoke · data-fp="FP-04"
前置条件单据状态 ∈ {待受理, 已受理} 且当前用户为主体管理员
可见性无权限用户不渲染该按钮（不是置灰）
② 交互详情
  1. 点击「撤回」→ 右侧抽屉打开，展示单号 + 主体 + 撤回后不可逆提示。
  2. 「撤回原因」多行必填，少于 10 字时提交按钮禁用并就地提示字数。
  3. 提交后行状态切换为「待审批」，操作列改为「查看进度」，成功 toast 带撤销入口（5s）。
  4. 驳回时回到「已受理」，并把驳回理由写进行内展开区，不弹全局弹窗。
  5. 并发保护：他人在同一单上已发起撤回时返回 409，就地提示「已在审批中」并刷新行。
③ 验收目标 可量化 · 可自动判定
目标判定方式
✓撤回原因 < 10 字时提交按钮禁用e2e 断言
✕撤回后状态流转到「待审批」，审批通过才落「已撤回」接口 + 状态机
✓并发撤回返回 409 且前端就地提示，不丢失列表状态集成测

验收目标逐条可被 Agent 读取：acceptance[] 里每条带 check 字段（e2e / api / state-machine / manual），越权与达成校验共用同一份。

回答你的问题：要加，而且这是整条链路能否自动校验的前提。需求层声明「我要动哪些功能点、各自意图」，任务层只能收窄不能扩大；Agent 改动时用声明集合做越权基线，验收时用功能点的验收目标做达成基线。表单里选模块后功能点跟着联动过滤，避免跨模块误绑。

画面 5 · 验收与越权：把「改了不该改的」和「该达成的没达成」变成一次可复跑的报告

原来的「规格覆盖率」TAB 被替换成这张验收与越权面板——覆盖率只是其中一个指标，真正要回答的是两件事：范围是否越权（实测改动 − 声明）、目标是否达成（验收目标逐条判定）。报告由 Agent 触发、结论落库，发布草案前必须为绿或人工豁免。
