## 1. 问题（用户截图 + 实码）

任务详情现在是**两套「动态」叠在一条长滚动里**，执行轨迹被挤进右侧属性栏。

| 区块 | 实码 | 用户看到的 |
|------|------|------------|
| 需求下钻 Tab | `IssueRequirementDrill`：动态 / 进度追踪 / 交付概览 | 第一套「动态」：五卡 + heartbeat / todo_change 流水 |
| 原生动态 | `issue-detail` 的 `activity_section` | 第二套「动态」：评论、取消、重试 |
| 执行日志 | 右侧栏 `ExecutionLogSection`（260–420px） | 运行列表；点开才弹 `AgentTranscriptDialog` |

后果：

1. 同一个词「动态」出现两次，职责不同（机器事件流 vs 人机协作流）。
2. 进度 / 交付被塞进下钻 Tab，和原生动态抢同一条滚动轴，切 Tab 后下面仍挂着第二套动态。
3. 执行步骤（思考 / 工具 / 文件）是排查失败的主证据，却放在最窄的一栏，且默认是折叠列表而不是轨迹。

---

## 2. 布局原则

1. **一条主轴、一套 Tab。** 下钻三 Tab 与原生「动态」合并为页级四 Tab，不再上下叠两套模块。
2. **按问题分面，不按数据源分面。** 人要对话去「动态」，要看树去「进度」，要复盘步骤去「执行」，要收产物去「交付」。
3. **右侧栏只放属性。** 状态 / 执行人 / 项目 / 模块 / 依赖 / PR / 详情。执行日志离开侧栏。
4. **机器噪声默认折叠。** heartbeat、todo_change 不属于协作动态；需要时在「执行」或「动态 → 系统进展」打开。
5. **常驻区不进 Tab。** 标题、描述、四阶段条、子任务始终在 Tab 之上，避免切面时丢上下文。

## 3. 目标信息架构

```
+-- 常驻 ------------------------------------------+-- 右侧属性 --+
| 面包屑 · 标题 · 状态 · 活跃运行 chip（进「执行」）| 状态/执行人  |
| 描述（可折叠）                                   | 项目/模块    |
| 四阶段条（仅顶层需求）                           | 日期/标签    |
| 子任务列表                                       | 依赖 / PR    |
+-- 页级 Tab --------------------------------------+ 创建信息    |
| 动态 | 进度 | 执行 | 交付                        |             |
| 主栏只渲染当前面，不再在 Tab 下再挂一套动态       | 无执行日志   |
+--------------------------------------------------+-------------+
```

| Tab | 回答的问题 | 承接的现有能力 | 不再放什么 |
|-----|------------|----------------|------------|
| **动态** | 人和 Agent 说了什么、状态怎么变的 | 原生评论时间线 + 需求动态里的对话 / 状态 / 产物 | heartbeat、步骤轨迹、进度树 |
| **进度** | 这棵需求树跑到哪、谁卡死 | `ProgressTracker`（L1 汇总 + L2 任务 + L3 run/todo） | 评论流、步骤明细 |
| **执行** | 这一次 run 想了什么、调了什么 | 原右侧运行列表 + `task-transcript` 主栏化 | 属性编辑、产物墙 |
| **交付** | 交了什么、门禁过了没 | `DeliverablesOverview` + 完成节点卡片墙 | 协作评论 |

默认落地：**有失败 / 进行中 run → 进度**；否则 **动态**。活跃运行 chip 始终可一跳到「执行」。

---

## 4. 各面要点

### 4.1 动态（协作流，只留一套）

- 默认过滤：评论、状态、产物开；**系统进展关**。
- 完成节点仍挂交付物卡片墙（已评审的 `DeliverablesSection`），点卡片预览，不替代「交付」Tab。
- 底栏评论输入只属于这一面。
- 不再渲染五张汇总卡（子任务 / Agent / 对话 / 进展 / 产物）——那些是进度与交付的数字，放到对应面。

### 4.2 进度（编排树）

- 保留现有 rollup 条、任务卡、卡死分布、血缘说明。
- 任务行可「查看此次执行」→ 切到执行 Tab 并选中对应 run。
- **本面底部不再复挂原生动态。**

### 4.3 执行（从侧栏升主栏）

左右分栏，不再弹窗才是主路径：

- 左：运行列表（进行中置顶，历史折叠），含重试 / 终止 / 费用。
- 右：选中 run 的思考 / 工具双轨时间轴 + 可搜索步骤流（现 `AgentTranscriptDialog` 的内容）。
- 窄屏：上列表、下轨迹，不回到右侧属性栏。

### 4.4 交付（收口）

- 派生状态、阶段门、产物网格、互斥 / 班底卡保持 `DeliverablesOverview`。
- 与动态里的完成卡片墙分工：动态看「这次完成带了什么」；交付看「整棵需求齐了没」。

### 4.5 右侧属性栏

只保留可编辑元数据与只读详情。可选：一枚「Qoder · 23m · 失败」chip，点击切到执行 Tab。不在此展开步骤。

---

## 5. 明确不做

- 不改四阶段流水线、拆解确认门、日历抽屉。
- 不新增后端实体；动态过滤与执行主栏化是组装，不是新机制。
- 不把进度树和步骤流合成一面（树看编排，流看证据，混在一起会再次噪声化）。
- 不删 `IssueRequirementDrill` 的数据查询，只改挂载位置与默认过滤。

---

## 6. 验收（布局层）

- [ ] 任务详情只出现一次「动态」标题 / Tab。
- [ ] 进度、执行、交付互斥，切面后主栏不再残留另一套动态。
- [ ] 右侧栏没有「执行日志」区块；运行列表出现在「执行」Tab。
- [ ] 默认动态流看不到 heartbeat / todo_change。
- [ ] 从进度任务行或顶栏 chip 能跳到指定 run 的轨迹。
- [ ] 顶层需求的四阶段条与子任务在切 Tab 时仍在。
